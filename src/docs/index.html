Quickstart

Three steps from zero to first completion:

  • 1. Create an account at modelaxis.ai and generate a key in the console. Keys look like mx-sk-….
  • 2. Point your OpenAI SDK at https://api.modelaxis.ai/v1.
  • 3. Pick any model id from the catalog — that's it.
# pip install openai
from openai import OpenAI

client = OpenAI(
    base_url="https://api.modelaxis.ai/v1",
    api_key="mx-sk-…",
)

reply = client.chat.completions.create(
    model="modelaxis/auto",  # or any model id
    messages=[{"role": "user", "content": "Hello, axis"}],
)
print(reply.choices[0].message.content)
// npm install openai
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.modelaxis.ai/v1",
  apiKey: process.env.MODELAXIS_API_KEY,
});

const reply = await client.chat.completions.create({
  model: "modelaxis/auto",
  messages: [{ role: "user", content: "Hello, axis" }],
});
console.log(reply.choices[0].message.content);
curl https://api.modelaxis.ai/v1/chat/completions \
  -H "Authorization: Bearer $MODELAXIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "modelaxis/auto",
    "messages": [{"role": "user", "content": "Hello, axis"}]
  }'

Authentication

Pass your key as a bearer token on every request. Keys are scoped: each key can carry its own model allowlist, spend budget, and rate limit, configured in the console.

Authorization: Bearer mx-sk-…

Never ship a key in client-side code. For browser apps, proxy requests through your backend or issue short-lived scoped keys from the console API.

Chat completions

POST /v1/chat/completions accepts the standard OpenAI request body, plus optional ModelAxis routing extensions:

FieldTypeNotes
modelstringAny catalog id, e.g. openai/gpt-5, or modelaxis/auto
messagesarrayOpenAI message format, including tool and image parts
streambooleanServer-sent events, OpenAI chunk format
toolsarrayFunction calling, passed through to models that support it
routeobjectModelAxis extension — see routing

Responses match the OpenAI schema exactly, with one addition: modelaxis.endpoint in the response metadata tells you which provider endpoint actually served the request, and at what price.

Streaming

Set stream: true to receive server-sent events. Chunks use the OpenAI delta format, so existing streaming parsers work unchanged. If a provider fails mid-stream, the axis re-issues the request to a fallback endpoint and resumes from the last complete token — your stream sees a brief pause, not an error.

Models & routing

Model ids are namespaced as provider/model. Three routing modes:

  • Pinned — "model": "anthropic/claude-sonnet-4.5": always this model, cheapest healthy endpoint.
  • Auto — "model": "modelaxis/auto": we pick the best price-performance model for the request's size and complexity.
  • Fallback chain — pass route.fallbacks and the axis walks the chain on any failure or rate limit.
{
  "model": "deepseek/deepseek-v3.2",
  "route": {
    "fallbacks": ["qwen/qwen3-235b-a22b", "meta-llama/llama-4-maverick"],
    "sort": "latency",          // or "price" (default)
    "data_policy": "zero-retention" // restrict to matching providers
  },
  "messages": […]
}

List every available model and its live prices with GET /v1/models.

Errors

Errors follow the OpenAI error envelope. Because of failover, most provider-side errors never reach you — these are the ones that can:

StatusCodeMeaning
400invalid_requestMalformed body, or a parameter the target model doesn't support
401invalid_api_keyMissing or revoked key
402insufficient_creditsBalance or budget exhausted — top up or raise the key's budget
403model_not_allowedModel outside this key's allowlist or data policy
429rate_limitedKey-level limit hit; axis-level limits are handled by failover
502all_endpoints_downEvery endpoint for the model (and fallbacks) is unavailable — rare

Rate limits

Default limits are per key and scale with your account tier: 600 RPM to start, rising automatically with sustained usage. Provider-side rate limits are absorbed by the axis — we spread your traffic across endpoints so a single provider's limit doesn't cap your throughput.

SDKs

Any OpenAI-compatible SDK works today: the official openai packages for Python and JavaScript, LangChain, LlamaIndex, Vercel AI SDK, LiteLLM, and most agent frameworks — just override the base URL. Native modelaxis packages with typed routing extensions are in beta.
